CHAPTER 01 · THE CONSTRAINT

故事從三個
「不能」開始。

不是缺功能，而是環境本身不允許用一般 IT 軟體的思路解題。

💾

不能留下安裝痕跡

還原卡讓 C 槽在重開機後回到原狀。傳統常駐安裝包沒有意義。

🪟

不能假設 Service 看得到桌面

Windows Session 0 與學生登入的 Session 1 隔離，背景服務不是理所當然的答案。

🌐

不能 70 台一起灌滿網路

1GbE LAN 下，高解析度全班串流會把瓶頸從 CPU 推到交換器與教師機。

所以第一個架構問題不是「畫面怎麼畫得漂亮」，而是：如何讓每台學生機只付得起它真正需要的成本？

三種模式，三種成本模型

70 台約 17 Mbps。監控是「偶爾更新的縮圖」，沒必要 30 FPS。

1080p @ 30 FPS · H.264 + RTP UDP Multicast

CHAPTER 04 · V5.0 → V5.2

技術做完了，
卻還不能叫做完成。

學校現場真正討厭的不是 bug，而是「需要教人怎麼安裝」。

1 秒加入教室

學生開啟 /join，一鍵複製 Win+R 指令。Agent 下載到 %TEMP%，直接在 Session 1 執行。

http://<TEACHER_IP>:3000/join ↓ 「複製連線指令」 ↓ Win + R → 貼上 → Enter ↓ gs-agent.exe · 無 UI · 無安裝

為什麼不用 navigator.clipboard？

因為教室現場可能就是 HTTP。於是退回 hidden textarea + document.execCommand('copy')，把瀏覽器安全限制變成相容性策略。

Windows Defender 也是產品的一部分

第三方單檔打包容易被判成未知威脅。於是改成綠色便攜包，使用官方簽章的原生 node.exe，讓部署路徑更可預期。

CHAPTER 06 · V5.4

真正的敵人
藏在「正常情況」裡。

多網卡、色彩轉換、Windows 批次檔、localhost 與真實 LAN IP——每個單獨看都很小，合在一起就是現場事故。

5.4.0

SSE2：把 BGRA → NV12 搬進 SIMD

30 FPS 高畫質推流時，色彩空間轉換成為 CPU 熱點。一次處理 16 pixels，讓編碼前的資料搬運更有效率。
5.4.0

Multi-NIC：先問「哪張網卡？」

實體 Ethernet、Wi-Fi、WSL、Hyper-V、VirtualBox 同時存在時，多播可能走錯路。啟動時掃描介面、過濾虛擬網卡，並提供 6 秒倒數選擇。
5.4.1–5.4.3

把 localhost 變成真的教室 IP

教師端可用 localhost 開頁面，但學生加入指令不能指向 localhost。前端透過 /api/server-info 動態校正 LAN IP。
CHAPTER 07 · V5.5 / V5.6

最後一幕不是新功能。
是把「會動」變成「可靠」。

近期 release 把重心放到 deadlock、UAF、WebSocket、RTP、auth、backpressure、health 與 CI。

THE SYSTEM TODAY

回頭看，GridSight 其實是一個成本分配器。

同一個教室，同一套 Agent，根據觀看需求切換不同資料路徑：低頻監控、單點即時、全班廣播。這才讓 70 台設備在 1GbE 環境下同時工作成為可控的工程問題。
