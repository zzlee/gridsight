# 🚀 未來功能企劃與目標清單 (Future Goals)

本文檔記錄 GridSight 未來預計加入的四大核心功能擴充計畫，包含技術可行性與預期實作方向。以下功能目前皆列為 **未來目標 (Future Goals)**。

---

## 1. 📡 學生示範廣播 (Student Showcase Relay)
- **目標**：允許教師選定某位學生的畫面，並將其畫面作為「示範畫面」即時推流轉播給全班所有學生觀看。
- **實作考量**：
  - **抑制無限遞迴 (Anti-Mirroring)**：當該名示範學生自己也在接收全班廣播時，系統必須在其本機端抑制「自己觀看自己」的全螢幕廣播彈出，否則將產生無限鏡像迴圈。此部分已在部分實作中規劃。
  - **轉播管線架構**：
    1. **方案A (Teacher Relay)**：示範學生透過反向 WebSocket 將 H.264 串流推給教師 Node.js 伺服器，再由教師伺服器重新封裝為 RTP 多播 (Multicast) 發送給全班。此方案延遲較低，並由教師機集中管控流量。
    2. **方案B (P2P / Direct Multicast)**：直接指示示範學生端啟動多播推流，其他學生改聽該學生的 IP。

## 2. 🖱️ 廣播視窗滑鼠自動跟隨 (Auto-Tracking Mouse on Broadcast)
- **目標**：在接收廣播畫面的全螢幕視窗或子母視窗中，當教師將游標移動至畫面邊緣外時，廣播視窗的 viewport 能夠自動跟隨教師滑鼠的座標進行平滑捲動與縮放。
- **實作考量**：
  - **游標座標擷取**：需要在目前的 DXGI / GDI+ 擷取管線外，額外附帶精準的滑鼠座標中繼數據。
  - **平滑插值 (Smooth Interpolation)**：前端或 Win32 GDI 接收端需要實現基於彈簧模型 (Spring Physics) 或線性插值的自動平移演算法，避免畫面撕裂或跳動。
  - **防暈眩 (Anti-Motion Sickness)**：當快速甩動滑鼠時，需設置跟隨速度上限 (Velocity Clamping)。

## 3. 🖥️ 廣播視窗全螢幕模式 (Immersive Fullscreen Broadcast)
- **目標**：當學生端接收到教師畫面時，預設或可選擇進入真正的全螢幕沉浸模式，隱藏所有 Windows 工具列與視窗邊框。
- **實作考量**：
  - **純淨渲染 (Pure Canvas)**：在 `rtp_receiver.cpp` 中的 Win32 視窗需正確處理 `WS_POPUP` 樣式並覆蓋 Taskbar，支援多螢幕 (Multi-Monitor) 環境下的全螢幕擴展。
  - **跳脫機制 (Escape Hatch)**：必須實作安全的跳脫機制（如長按 ESC 或特定組合鍵），避免因網路中斷或 Bug 導致學生電腦被永久鎖定在黑畫面中。
  - **與現有置頂機制的整合**：目前已實作部分置頂 (TopMost) 邏輯，需進一步與嚴格的全螢幕模式區分開來。

## 4. 🆔 學號登錄 (Student ID Login System)
- **目標**：讓學生能主動輸入或由系統派發唯一的「學號」，以此取代單純的 MAC 位址或隨機產生的 Token 作為系統核心識別碼。
- **實作考量**：
  - **身分綁定 (Identity Binding)**：教師端需要提供匯入名單 (CSV) 的介面，並在 `seats.json` (或新的資料庫結構中) 建立 `{ mac: "00-11-22-...", studentId: "1120001", name: "王大明" }` 的對應關係。
  - **自動化或自助登錄**：若為固定座位制，可延續現有的固定佈局分配；若為流動座位制，學生端 Agent 需實作一個輕量的 Win32 彈窗讓學生輸入學號密碼，或結合學校現有 LDAP/OAuth 系統登入。
  - **狀態隔離**：學生下課登出後，必須確保下一個使用者登入時，過往的截圖或離題記錄不會被誤判給新學生。
